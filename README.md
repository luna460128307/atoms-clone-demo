# Atoms Clone Demo —— Agent 驱动的应用生成器

一个参考 [atoms.dev](https://atoms.dev/) 交互体验实现的可运行 Demo：用户用一句自然语言描述想要的应用，"多智能体团队"（PM / 架构师 / 工程师 / QA）协作分析需求、设计数据模型、生成代码，最终产出一个真实可交互、数据可持久化的小应用，并可在页面右侧实时预览与操作。

> **新增增强（2026-08）：** 本项目已推送到 GitHub，并添加了演示账号快速体验、移动端响应式适配、生产环境部署配置等，已超出纯 PoC 水平，可作为实际可用的功能级 Demo。

## 快速体验

### 方式一：在线访问（无需安装）

1. 打开 [在线 Demo](https://thick-numbers-speak.loca.lt)
2. 点击登录页的 **⚡ 快速体验（演示账号）** 按钮，一键进入，无需注册
3. 系统已预置两个示例应用（待办清单 + 投票调查），可直接在右侧面板操作
4. 在左侧对话框输入新的需求描述，AI 智能体团队会帮你生成新的应用

### 方式二：本地运行

```bash
cd atoms-clone-demo
npm install
npm start
# 访问 http://localhost:3000
```

Node.js 版本要求 >= 18。首次访问可注册账号（用户名至少 3 位，密码至少 6 位），所有数据保存在 `data/store.json` 中，重启服务不会丢失。也可直接点击「快速体验」使用演示账号。

## 核心交互流程

1. 注册 / 登录 / 演示账号快速体验（服务端 session + bcrypt 密码哈希 + JSON 文件持久化）。
2. 在左侧对话框输入一句需求描述，例如"帮我做一个待办事项清单"。
3. 对话区实时展示 PM Agent → Architect Agent → Engineer Agent → QA Agent 四个角色依次产出的分析过程（需求解析、数据建模、接口与代码生成、自测校验）。
4. 智能体协作过程播放完毕后，先展示一张虚线边框的"生成计划"确认卡片（模板类型、字段设计摘要），用户点击「确认并生成」才会真正创建应用并落库；点击「重新描述」可以直接放弃本次计划、重新输入需求，不会产生垃圾数据。
5. 确认后自动在右侧面板中加载一个真实可交互的应用（真实的表单提交、勾选、点赞、投票、状态流转、库存加减、指标录入等操作，均落库持久化）。
6. 侧边栏保存历史生成记录，可随时切换回看、删除，或对已有应用重新生成（迭代需求）。
7. 支持将生成应用的完整源码打包为 zip 下载，解压后 `npm install && npm start` 即可独立运行，脱离本平台单独使用。

## 已实现的功能（超越 PoC）

- **演示账号一键体验**：无需注册即可快速体验，自动预置示例数据（待办事项 + 投票），降低评审者的体验门槛
- **移动端响应式适配**：针对 900px（平板）、700px（折叠屏）、480px（手机）做了三档断点适配，侧边栏收缩、聊天面板纵向堆叠
- **生产环境部署就绪**：
  - Session Cookie 的 `secure` / `sameSite` 自动根据 `NODE_ENV` 切换
  - 提供 `render.yaml` 一键部署配置（Render 免费 tier）
  - 提供 `.env.example` 环境变量模板
  - 新增 `/api/health` 健康检查接口，便于部署平台监控
- **数据完整性校验**：服务端对 `select` 枚举值和 `number` 的 `min` 下限都做了 POST/PATCH 两端的防御性校验，绕过前端直接调用 API 也无法破坏数据
- **诚实的兜底策略**：当需求无法匹配任何预置模板时，明确告知用户"未能精确匹配到预置模板"，而不是静默降级成无关模板
- **两步式生成确认**：先出计划、用户确认后再真正创建，避免 Agent 理解偏差导致生成垃圾数据
- **数据看板真实聚合**：基于用户实际提交的指标记录分组求和，动态计算统计卡片和柱状图，看到的数字都是真的

## 部署指南

### 部署到 Render（推荐，免费 tier）

1. Fork 本仓库到你的 GitHub 账号
2. 登录 [Render](https://render.com) → New Web Service → Connect GitHub repo → 选择 `atoms-clone-demo`
3. 构建命令：`npm install`
4. 启动命令：`npm start`
5. 添加环境变量：`SESSION_SECRET` = 随机字符串，`NODE_ENV` = production
6. 点击 Deploy，约 2 分钟后获得固定域名

> 项目根目录已包含 `render.yaml`，支持 Render Blueprint 一键部署（Build Command / Start Command / Health Check Path 均已配置好）。

### 部署到 Railway / Vercel / Fly.io

本项目基于 Express + Node.js >= 18，零原生依赖，可部署到任何支持 Node.js 的 PaaS 平台：

- **Railway**：导入 GitHub 仓库即可自动识别 Node.js 项目
- **Vercel**：需要将 Express 转换为 Serverless Function 形式（使用 `api/index.js` 入口）
- **Fly.io**：使用 `fly launch` + `fly deploy`，支持持久化 Volume

## 实现思路与关键取舍

**为什么不接入真实大模型 API：** 评审 / 演示环境通常无法保证外部 LLM API Key、网络出口和调用额度稳定可用，一旦生成失败会导致"Demo 在别人电脑上跑不起来"的尴尬局面。因此本 Demo 用"关键词匹配 + 模板渲染"的规则引擎（`server/agentEngine.js`）模拟多智能体的分工产出，重点保证生成出的应用是真实、可交互、可持久化的产品，而不是一段假动画。引擎与运行时之间做了解耦：如果未来要换成真实 LLM 驱动的代码生成，只需要替换 `agentEngine.js` 里的 `planWithAgents`（输入需求文本，输出模板配置 + 分析过程文案），不需要改动运行时、存储层、前端交互逻辑。

**为什么用 JSON 文件持久化而不是 SQLite/MySQL：** 最初尝试用 `better-sqlite3`，但它依赖原生编译（node-gyp），在当前沙箱环境的 Xcode Command Line Tools 版本探测上直接编译失败，且很多零成本部署平台对原生模块支持有限，容易出现"本地能跑、线上跑不起来"的问题。改用一个基于 JSON 文件、带写队列串行化和原子替换的极简数据库封装（`server/db.js`），零原生依赖，读写效率对 Demo 级别的数据量完全够用，且是真实落盘而非内存假数据，重启服务、关闭浏览器都不会丢失数据（已通过重启进程后数据仍在的测试验证）。

## 已知限制

- 未接入真实大模型，需求理解停留在关键词匹配层面，无法处理关键词库之外的复杂/组合型需求
- 数据库是单文件 JSON，未做索引和分页，数据量增长后需要迁移到真正的数据库
- 未做多人协作、团队空间等企业级功能
- session 采用内存存储，服务进程重启会导致登录态失效（数据本身不受影响）
- 未加限流、验证码等防刷机制，仅适合 Demo 级别的可信环境使用

## 未来延展方向

如果继续投入，优先级从高到低建议：其一，替换 `agentEngine.js` 为真实 LLM 驱动（可接入的模型不限），把"关键词匹配"升级为"自由文本理解 + 代码级生成"，同时保留现在的模板机制作为生成失败时的兜底与效果对照基线；其二，把 JSON 文件存储替换为真正的数据库（如 PostgreSQL/MySQL），支持多用户高并发写入与更复杂的数据查询；其三，支持模板可插拔机制，允许生成"字段级自定义"的应用而不局限于现有八套预置模板，比如让 Architect Agent 可以动态定义任意字段组合；其四，补充团队协作、应用发布分享（生成一个公开可访问的短链接给应用，类似 Atoms 的"一键发布"）、内置支付/登录等生产级组件模板。
